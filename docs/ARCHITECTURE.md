# 实现说明

## 官方核心和自有工具

自有 C# 工具管理安装位置、权限、服务、回退、离线规则和日常启动；官方核心负责设备协议与 G HUB 功能。
`frontend/offline-mode.cjs` 是自有 Electron 请求限制层，其测试使用模拟 Electron 对象，不包含官方 JavaScript。

这一实现没有把整个 G HUB 重写成独立的开源应用，也没有保证原生核心不发起任何联网请求。
默认模式通过请求拦截和 Windows 防火墙阻止外部连接，并移除启动环境中的代理变量。

## 文件和系统状态

实际文件放在用户选择的目录：`App/`、`Data/Profile/`、`Data/System/`、`Data/Control/` 和 `Backups/`。
为了兼容官方核心，程序目录和几个已知的 AppData/ProgramData 路径使用 NTFS 目录联接指向实际目录。
后台使用 `LGHUBUpdaterService`，虚拟 HID 驱动仍由 Windows 管理。

恢复记录存放于 ProgramData 中受管理员保护的事务目录。日常入口是安装目录内的 EXE，桌面快捷方式直接指向它，不通过 VBS 或 PowerShell 启动。

## 权限与回退

LocalSystem 服务的可执行文件及路径不能允许普通用户替换。因此安装器保存权限快照，保护程序目录与必要祖先目录本身，同时保留其他子项的继承模板。
失败回退或解除安装先停止相应服务、移除本次联接，再恢复祖先权限，最后恢复安装目录的继承权限。
权限比较将效果相同的拆分/合并 ACE 按作用范围归一化，保留所有者、继承保护、allow/deny 和传播范围区别。

## 驱动完成条件

官方驱动安装进程退出并不意味着 Windows PnP 已同步完成所有文件替换。
安装器最多等待 30 秒，要求三个驱动文件连续三次稳定可读，记录解析后的路径和错误。
驱动安装超过限定时间仍在运行时，不强制终止驱动进程，也不放宽其程序路径权限。

## 网络边界

为已盘点的每个官方可执行文件及其兼容路径建立专属出站规则：阻断外部 IPv4/IPv6，限制回环 TCP 到已知本机端口，阻断回环 UDP。
修改模式之前验证规则名称、程序路径、协议和行为，遇到冲突停止操作，不修改全局防火墙开关。

该策略依赖操作系统、防火墙和本机其他服务，不能被解释为对恶意进程或所有代理机制的隔离保证。
